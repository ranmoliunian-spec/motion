# 提示词档案 · Prompts

这份文档把本项目从「一句话需求」到「成片」全过程中**真实使用过的提示词**完整留档，
并把它抽象成可复用的模板，方便你换一个主题直接套用。

---

## 关于这份文档的边界（先说实话）

- 以下**第 0 层**是发起这个项目时使用的**原始需求提示词全文**，一字未改。
- **第 2 层**是项目推进过程中逐步确立、并被确认采纳的**工程约束**。它们不是「一次性发给 AI 的台词」，
  而是贯穿始终的设计原则 —— 每一条都对应仓库里实际存在的代码，可逐条对照验证。
- **第 3、4 层**是我从这次实践里反推出来的**可复用模板**，属于提炼，不是当时的原始输入。
- 我只能留档**本项目相关**的提示词。其它历史对话中的提示词不在本文档范围内。

标注清楚来源，是为了让这份档案能被信任 —— 混着写的提示词文档没有复用价值。

## 第 0 层 · 原始需求提示词（全文引用）

这是本项目的起点，也是最有参考价值的一段：**没有描述画面，只描述了链路与风格**。

```text
- 旁白：把每个场景的中文文案分别交给 edge-tts，生成 MP3，再按场景时间点放进视频。
- 背景音乐：用 Python 的 NumPy 按音符逐样本合成：导出 WAV。
- 混音：Remotion 把旁白和音乐合到视频里；最终视频音轨编码为 AAC 立体声。
用 Remotion（基于 React 的视频制作工具）把标题、贴纸卡片、图标、箭头和进度条做成组件；
场景切换、弹入、轻微旋转和缩放都由代码控制

做一个浙江金融职业学院的宣传片，然后时长在两分钟，做一个贴纸科普风的横屏16：9视频
```

后续仅追加过一句：

```text
请继续执行任务
```

### 这段提示词好在哪（值得照抄的结构）

| 手法 | 这段里的体现 | 作用 |
| --- | --- | --- |
| **指定链路而非结果** | 「交给 edge-tts」「NumPy 逐样本合成」「Remotion 混音」 | 直接锁死技术栈，省掉选型往返 |
| **点明汇合点** | 「混音：Remotion 把旁白和音乐合到视频里」 | 说清三条链在哪里相遇 |
| **锁定编码规格** | 「AAC 立体声」 | 交付标准明确、可验收 |
| **点名要组件化的东西** | 「标题、贴纸卡片、图标、箭头和进度条做成组件」 | 直接给出组件清单，避免交付成一坨硬编码 |
| **点明动效归属** | 「切换、弹入、轻微旋转和缩放都由代码控制」 | 提前排除「用现成模板/素材拼」的路线 |
| **三要素收口** | 主题 + 时长 + 风格 + 画幅 | 剩下的创作空间留给执行方 |

**核心经验**：说清「用什么做、在哪汇合、交付什么规格」，比说清「画面长什么样」更有用。
画面风格用一个词（贴纸科普风）就够，其余交给组件系统。

## 第 1 层 · 从需求拆出的硬规格

执行时先把提示词里的硬指标固定成一份可验收清单（对应仓库里的实现）：

| 项 | 规格 | 落在哪 |
| --- | --- | --- |
| 时长 | 120.000 秒 = 3600 帧 @30fps（精确卡死） | `script/build_timeline.py` 强制对齐 |
| 画幅 | 横屏 16:9 / 1920×1080 / 30fps | `src/Root.tsx` |
| 旁白 | 每场景独立 MP3，按场景时间点落位 | `script/tts.py` → `src/Video.tsx` `<Sequence>` |
| 背景音乐 | NumPy 逐音符样本合成 → WAV | `script/bgm.py` |
| 混音 | 旁白 + 音乐在 Remotion 汇合，音轨 AAC 立体声 | `src/Video.tsx` + 渲染参数 |
| 画面 | 全组件化，动效全由代码控制 | `src/components/` |

## 第 2 层 · 贯穿全程的工程约束（设计原则）

这些约束在实现中被确立并一直生效，是本项目「不是一次性作品、而是可复用系统」的原因。
每一条都可对照代码验证。

### 2.1 禁止硬编码，一切走设计令牌

> 所有颜色、字体、投影、间距必须集中在 `theme.ts`，组件里不允许出现魔法数字色值。

对应实现：`src/theme.ts` —— 纸感底色、三级墨色、5 组强调色（各带 soft 变体）、
字体栈、硬投影函数 `hardShadow()`、透明度混合 `hexA()`、贴纸文字生成器 `stickerText()`。

### 2.2 原子组件优先，场景只做编排

> 场景文件里只允许「摆放原子组件 + 传参」，不允许出现内联的复杂样式拼装。

对应实现：`PopIn / Wiggle / Float`（动效原语）、`StickerCard / StickerText / Chip / Tape / StatBlock`
（贴纸体系）、`Icon + IconBadge`（32 个图标）、`Arrow / ArrowDown`（手绘箭头）、
`SceneFrame`（统一入出场语法）。10 个场景文件全部由这些原子拼装。

### 2.3 时间轴必须脚本生成，不许手工对轴

> 文案改一个字，进度条、章节标签、旁白落位必须全部自动跟上，不允许人工重算。

对应实现：`script/build_timeline.py` —— 用 ffprobe 测每段 MP3 的**真实时长**，
按旁白长度加权分配场景 slot，强制总帧数等于 3600，写出 `src/timeline.json`。
`Chrome.tsx` 的进度条与章节标签全部读它 → **增删场景不用改组件**。

### 2.4 零外部素材依赖

> 不使用任何图片、图标、音效素材库；插画与音乐必须由代码生成。

对应实现：`Illustration.tsx` 五组原创 SVG 插画；`bgm.py` 从振荡器开始逐样本合成。

### 2.5 混音要有依据，不许凭感觉

> 每个增益值必须由实测电平反推，不能拍脑袋。

对应实现：`bgm.py` 输出母版后实测 `mean -29.6dB`，旁白 `mean ≈ -19dB`，
据此把 BGM 基准定为 0.76、躲让值定为 0.40，并在 `Video.tsx` 注释里写明标定依据。

### 2.6 交付必须自检

> 出片后必须抽帧检查画面 + 测量音频电平，不允许「渲染成功即交付」。

对应实现：抽 10 个场景的关键帧目视复核；`ffprobe` 校验编码规格；`volumedetect` 校验混音。

## 第 3 层 · 可复用提示词模板（换主题即用）

把第 0 层的结构抽象成填空模板：

```text
【三条链】
- 旁白：把每个场景的中文文案分别交给 edge-tts，生成 MP3，再按场景时间点放进视频。
- 背景音乐：用 Python 的 NumPy 按音符逐样本合成，导出 WAV。
- 混音：<视频框架> 把旁白和音乐合到视频里；最终视频音轨编码为 AAC 立体声。

【画面】
用 <视频框架> 把标题、贴纸卡片、图标、箭头和进度条做成组件；
场景切换、弹入、轻微旋转和缩放都由代码控制。

【约束】
- 所有颜色 / 字体 / 投影集中在一处设计令牌，组件里不许出现魔法数字。
- 场景文件只做编排，只能摆放原子组件与传参，不许内联复杂样式。
- 时间轴由脚本测量音频真实时长自动生成，改文案后进度条与落位必须自动跟上。
- 不使用任何外部图片 / 音效素材，插画与音乐全部代码生成。
- 混音增益必须由实测电平反推，不许凭感觉。

【交付】
做一个 <主体> 的宣传片，时长 <N> 分钟，<风格> 的横屏 16:9 视频。
```

> 把第 2 层的六条约束显式写进提示词，是本项目能「一次搭成系统、而非堆出一支片子」的关键。
> 不写这几条，多半会得到一个能跑但改不动的结果。

## 第 4 层 · 迭代与返工提示词（实战记录）

首轮成片出来后发现的真实问题，以及对应的返工要求。这类「带着证据提要求」的写法，
比「感觉不太对」有效得多 —— 每条都能直接定位到代码。

| 发现的问题 | 证据 | 返工要求 | 实际改动 |
| --- | --- | --- | --- |
| 贴纸数字全变成白色 | 抽帧图里 51 / 5000+ / 7万+ / 32 全是白的 | 数字应显示所属场景的强调色 | `StickerText` 不读 `style.color`，被默认白色覆盖；5 处改为具名 `color={}` 参数 |
| 卡片内容溢出边框 | S4 / S7 的文字压到卡片边框外 | 收窄内容或加高卡片 | 调高度、收窄内容宽度 |
| S8 卡片右侧越界且飞机被挡住 | 抽帧右侧出画 | 把飞行轨迹重排到留白区 | 重排贝塞尔曲线与卡片布局 |
| 音乐几乎听不见 | `volumedetect`：纯音乐段 -43.5dB，旁白段 -22dB（差 21dB） | 抬升音乐床，重新标定躲让比 | 提升 BGM 片头稀疏段编排（补贝斯 / 沙锤 / 钟琴）+ 增益重标定 |

**最终实测**：纯音乐间隙 -30 ~ -36dB，旁白段 -22dB，全片峰值 -5.8dB 无削波。

### 提示词写法要点

1. **带证据**：「抽帧图里数字全是白的」比「颜色不对」好定位。
2. **给判据**：「音乐要比旁白低 10~12dB」比「音乐小一点」可验收。
3. **说清期望行为**：「数字应显示所属场景的强调色」而不是「改一下颜色」。
4. **一次只提能验证的点**：每轮返工都对应一次抽帧或一次电平测量。

## 附：环境相关的提示词（非业务，但当时确实需要）

本机执行时踩到过两个与提示词无关、但需要显式交代的执行环境问题，一并留档：

1. **前端命令被中断** → 改为后台方式执行。
2. **Remotion 渲染被文件系统代理拦截**（`EEXIST ... node-brokered-fs-shim`）：
   根因是 `NODE_OPTIONS` 被注入了 fs 代理 shim。解法是在渲染命令前绕开它：

   ```bash
   env -u NODE_OPTIONS CODEBUDDY_BROKERED_FS_HOOK_ENABLED=0 npx remotion render ...
   ```

   该问题是特定运行环境的注入行为，普通本地开发不会遇到，仅作记录。
